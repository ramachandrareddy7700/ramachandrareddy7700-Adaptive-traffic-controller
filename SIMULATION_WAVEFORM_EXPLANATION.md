# Simulation Waveform Explanation
## Adaptive Traffic Controller - Expected Behavior and Signal Analysis

---

## Overview

This document explains what to expect when viewing the simulation waveforms generated by the testbench. The waveform file (`adaptive_traffic_controller.vcd`) can be viewed using tools like GTKWave, ModelSim, or any VCD-compatible waveform viewer.

---

## Key Signals to Monitor

### 1. Control Signals
| Signal | Width | Description |
|--------|-------|-------------|
| `clk` | 1-bit | System clock (100 MHz, 10ns period) |
| `rst_n` | 1-bit | Active-low asynchronous reset |

### 2. Traffic Density Inputs
| Signal | Width | Description |
|--------|-------|-------------|
| `traffic_north[1:0]` | 2-bit | North direction traffic density |
| `traffic_south[1:0]` | 2-bit | South direction traffic density |
| `traffic_east[1:0]` | 2-bit | East direction traffic density |
| `traffic_west[1:0]` | 2-bit | West direction traffic density |

**Encoding**: 00=Low, 01=Medium, 10=High, 11=Very High

### 3. Emergency Override
| Signal | Width | Description |
|--------|-------|-------------|
| `emergency_override` | 1-bit | Emergency activation (1=active) |
| `emergency_dir[1:0]` | 2-bit | Emergency direction (00=N, 01=S, 10=E, 11=W) |
| `emergency_active` | 1-bit | Emergency mode indicator output |

### 4. Traffic Light Outputs
| Signal | Width | Format | Description |
|--------|-------|--------|-------------|
| `lights_north[2:0]` | 3-bit | [R,Y,G] | North lights (100=Red, 010=Yellow, 001=Green) |
| `lights_south[2:0]` | 3-bit | [R,Y,G] | South lights |
| `lights_east[2:0]` | 3-bit | [R,Y,G] | East lights |
| `lights_west[2:0]` | 3-bit | [R,Y,G] | West lights |

### 5. Internal State Information
| Signal | Width | Description |
|--------|-------|-------------|
| `current_state[3:0]` | 4-bit | Current FSM state |
| `dut.timer[15:0]` | 16-bit | Internal countdown timer |
| `dut.next_state[3:0]` | 4-bit | Next state (combinational) |

---

## State Value Reference

| State Name | Value (Hex) | Value (Decimal) | Description |
|------------|-------------|-----------------|-------------|
| IDLE | 4'h0 | 0 | Initial state |
| NORTH_GREEN | 4'h1 | 1 | North has green light |
| NORTH_YELLOW | 4'h2 | 2 | North has yellow light |
| SOUTH_GREEN | 4'h3 | 3 | South has green light |
| SOUTH_YELLOW | 4'h4 | 4 | South has yellow light |
| EAST_GREEN | 4'h5 | 5 | East has green light |
| EAST_YELLOW | 4'h6 | 6 | East has yellow light |
| WEST_GREEN | 4'h7 | 7 | West has green light |
| WEST_YELLOW | 4'h8 | 8 | West has yellow light |
| EMERGENCY | 4'h9 | 9 | Emergency override mode |
| ALL_RED_STATE | 4'hA | 10 | All directions red |

## Test Case Waveform Analysis

### Test Case 1: Normal Traffic Flow (Low Density)

**Duration**: ~0 to 2000ns

**Initial Conditions**:
- All traffic densities: `2'b00` (Low)
- No emergency override
- System reset at start

**Expected Waveform Behavior**:

1. **Reset Phase (0-70ns)**:
   ```
   rst_n:           0 → 1 (at 50ns)
   current_state:   X → 0 (IDLE)
   All lights:      XXX → 100 (RED)
   ```

2. **State Sequence**:
   ```
   Time Range    | State          | North  | South | East  | West  | Timer Value
   ----------------------------------------------------------------------------
   70-90ns       | ALL_RED_STATE  | RED    | RED   | RED   | RED   | 2→1→0
   90-190ns      | NORTH_GREEN    | GREEN  | RED   | RED   | RED   | 10→...→0
   190-220ns     | NORTH_YELLOW   | YELLOW | RED   | RED   | RED   | 3→2→1→0
   220-240ns     | ALL_RED_STATE  | RED    | RED   | RED   | RED   | 2→1→0
   240-340ns     | SOUTH_GREEN    | RED    | GREEN | RED   | RED   | 10→...→0
   340-370ns     | SOUTH_YELLOW   | RED    | YELLOW| RED   | RED   | 3→2→1→0
   ... (pattern continues for EAST and WEST)
   ```

3. **Key Observations**:
   - Each green phase lasts exactly 10 clock cycles (low traffic = 10)
   - Yellow phase always lasts 3 clock cycles
   - All-red safety interval lasts 2 clock cycles
   - Cycle repeats: N → S → E → W → N...

4. **Signal Patterns**:
   ```
   lights_north:  100 → 001 (GREEN for 10 cycles) → 010 (YELLOW for 3) → 100
   lights_south:  100 (throughout NORTH phases) → 001 (GREEN) → 010 → 100
   ```

### Test Case 2: Adaptive Timing with Varying Densities

**Duration**: ~2000 to 6000ns

**Traffic Density Settings**:
```
traffic_north = 2'b11 (Very High) → 40 cycle green
traffic_south = 2'b01 (Medium)    → 20 cycle green
traffic_east  = 2'b00 (Low)       → 10 cycle green
traffic_west  = 2'b10 (High)      → 30 cycle green
```

**Expected Waveform Behavior**:

1. **North Green Phase**:
   ```
   State: NORTH_GREEN
   Duration: 40 clock cycles (400ns at 10ns period)
   Timer: Loads 40, counts down 40→39→38→...→1→0
   lights_north: 001 (GREEN)
   ```

2. **South Green Phase**:
   ```
   State: SOUTH_GREEN
   Duration: 20 clock cycles (200ns)
   Timer: Loads 20, counts down
   lights_south: 001 (GREEN)
   ```

3. **East Green Phase**:
   ```
   State: EAST_GREEN
   Duration: 10 clock cycles (100ns) - SHORTEST
   Timer: Loads 10, counts down
   lights_east: 001 (GREEN)
   ```

4. **West Green Phase**:
   ```
   State: WEST_GREEN
   Duration: 30 clock cycles (300ns)
   Timer: Loads 30, counts down
   lights_west: 001 (GREEN)
   ```

5. **Adaptive Timing Verification**:
   - Measure green phase durations in waveform viewer
   - Verify: North (40) > West (30) > South (20) > East (10)
   - Confirms adaptive logic is working correctly

**GTKWave Measurement**:
```
1. Place cursor at NORTH_GREEN entry
2. Place second cursor at NORTH_YELLOW entry
3. Read time difference = 400ns = 40 cycles ✓
```

### Test Case 3: High Traffic Condition

**Duration**: ~6000 to 11000ns

**Traffic Density Settings**:
```
All directions = 2'b10 (High) → 30 cycle green for each
```

**Expected Waveform Behavior**:

1. **Uniform Green Durations**:
   - All four directions get 30-cycle green phases
   - Timer loads 30 at each GREEN state entry
   - Fair distribution of time

2. **State Sequence**:
   ```
   N_GREEN (30 cyc) → N_YELLOW (3) → ALL_RED (2) →
   S_GREEN (30 cyc) → S_YELLOW (3) → ALL_RED (2) →
   E_GREEN (30 cyc) → E_YELLOW (3) → ALL_RED (2) →
   W_GREEN (30 cyc) → W_YELLOW (3) → ALL_RED (2) → [repeat]
   ```

3. **Cycle Time Calculation**:
   - One complete cycle = 4 × (30 + 3 + 2) = 4 × 35 = 140 clock cycles
   - At 10ns per cycle = 1400ns per complete rotation

### Test Case 4: Emergency Override Scenario

**Duration**: ~11000 to 15000ns

**Most Critical Test Case**

**Scenario 4a: Emergency Override to EAST during North Green**

1. **Initial State (before emergency)**:
   ```
   Time: ~11100ns
   State: NORTH_GREEN
   lights_north: 001 (GREEN)
   traffic densities: Medium (2'b01) for all
   ```

2. **Emergency Activation**:
   ```
   Time: ~11200ns
   emergency_override: 0 → 1
   emergency_dir: 2'b10 (EAST)
   ```

3. **Immediate Response**:
   ```
   Within 1-2 clock cycles:
   current_state: NORTH_GREEN (1) → EMERGENCY (9)
   lights_north: 001 (GREEN) → 100 (RED)
   lights_east:  100 (RED) → 001 (GREEN)
   emergency_active: 0 → 1
   timer: Reloads to 30 (emergency duration)
   ```

4. **Key Waveform Features**:
   ```
   ┌─────────────────────────────────────────────────────────┐
   │ emergency_override  ___________                         │
   │                  __|           |________________________ │
   │                                                          │
   │ current_state    [NORTH_GREEN][EMERGENCY][ALL_RED]...   │
   │                  [     1     ][    9    ][  10  ]...    │
   │                                                          │
   │ lights_east      [RED  ][GREEN          ][RED    ]...   │
   │                  [100  ][001            ][100    ]...   │
   │                                                          │
   │ emergency_active ______________________                 │
   │                 |                      |________________ │
   └─────────────────────────────────────────────────────────┘
   ```

5. **Emergency Hold and Release**:
   ```
   Emergency duration: 30 clock cycles
   timer: 30 → 29 → ... → 1 → 0
   
   At timer=0 and emergency_override=0:
   State transitions to ALL_RED_STATE
   Then resumes normal cycle from NORTH_GREEN
   ```

**Scenario 4b: Second Emergency Override to WEST**

1. **Emergency Activation**:
   ```
   Time: ~11900ns
   emergency_override: 0 → 1
   emergency_dir: 2'b11 (WEST)
   ```

2. **Behavior**:
   - Immediate interruption of current state
   - West gets green instantly
   - Pattern similar to Scenario 4a

**Critical Verification Points**:
- Emergency takes effect within 1 clock cycle
- Correct direction gets green immediately
- `emergency_active` flag asserts
- Timer properly reloads
- System safely returns to normal operation after emergency clears

### Test Case 5: Complete Cycle Verification

**Duration**: ~15000 to 21000ns

**Purpose**: Verify correct state sequencing

**Expected State Sequence**:
```
NORTH_GREEN → NORTH_YELLOW → ALL_RED →
SOUTH_GREEN → SOUTH_YELLOW → ALL_RED →
EAST_GREEN  → EAST_YELLOW  → ALL_RED →
WEST_GREEN  → WEST_YELLOW  → ALL_RED →
[Cycle repeats back to NORTH_GREEN]
```

**Waveform Analysis**:
1. Monitor `current_state[3:0]` signal
2. Verify sequence: 1 → 2 → 10 → 3 → 4 → 10 → 5 → 6 → 10 → 7 → 8 → 10 → 1...
3. Each state should appear in order
4. No state skipped or repeated incorrectly

### Test Case 6: Safety Checks

**Duration**: ~21000 to 29000ns

**Purpose**: Verify no conflicting green lights

**Safety Invariants** (must hold at ALL times):
```
1. lights_north[0] AND lights_south[0] = 0  (No N+S green simultaneously)
2. lights_north[0] AND lights_east[0]  = 0  (No N+E green simultaneously)
3. lights_north[0] AND lights_west[0]  = 0  (No N+W green simultaneously)
4. lights_south[0] AND lights_east[0]  = 0  (No S+E green simultaneously)
5. lights_south[0] AND lights_west[0]  = 0  (No S+W green simultaneously)
6. lights_east[0]  AND lights_west[0]  = 0  (No E+W green simultaneously)
```

**Waveform Verification**:
- Add a "derived signal" in GTKWave combining green bits:
  ```
  green_count = lights_north[0] + lights_south[0] + 
                lights_east[0] + lights_west[0]
  ```
- `green_count` should NEVER exceed 1
- If `green_count > 1` at any time → SAFETY VIOLATION

## Waveform Viewing Tips

### Recommended Signal Grouping in GTKWave

**Group 1: System Control**
```
+ clk
+ rst_n
```

**Group 2: Traffic Inputs**
```
+ traffic_north[1:0]
+ traffic_south[1:0]
+ traffic_east[1:0]
+ traffic_west[1:0]
```

**Group 3: Emergency**
```
+ emergency_override
+ emergency_dir[1:0]
+ emergency_active
```

**Group 4: FSM State**
```
+ current_state[3:0]    [Display as: Enum with state names]
+ dut.timer[15:0]       [Display as: Decimal]
```

**Group 5: Light Outputs**
```
+ lights_north[2:0]     [Display as: Enum - RED/YELLOW/GREEN]
+ lights_south[2:0]
+ lights_east[2:0]
+ lights_west[2:0]
```

### GTKWave Display Settings

1. **State Signal**:
   - Right-click `current_state`
   - Select "Data Format" → "Enum"
   - Add translations: 0=IDLE, 1=N_GRN, 2=N_YLW, etc.

2. **Light Signals**:
   - Display as binary [2:0]
   - Or create enum: 100=RED, 010=YLW, 001=GRN

3. **Timer Signal**:
   - Display as decimal (unsigned)
   - Shows countdown clearly

### Zoom Levels

**Full Test**: Zoom to see entire simulation (~29000ns)
- Good for overall behavior verification

**Individual Test**: Zoom to single test case (~3000-5000ns)
- Good for specific test analysis

**State Transition**: Zoom to 100-500ns
- Good for examining state changes and timing

**Single Cycle**: Zoom to 10-50ns
- Good for verifying clock edge behavior

## Debugging Tips

### Issue: States skipping
**Check**:
- Timer values loading correctly?
- State transition logic in FSM
- Reset not stuck low

### Issue: Wrong green duration
**Check**:
- `traffic_*` input values
- `calculate_green_time()` function
- Timer loading at state entry

### Issue: Multiple greens simultaneously
**Check**:
- Output logic in FSM
- Light assignments in each state
- ALL_RED_STATE functioning properly

### Issue: Emergency not activating
**Check**:
- `emergency_override` signal assertion
- `emergency_latched` internal signal
- Priority in next_state logic

## Measurements to Take

### Timing Measurements

1. **Green Phase Duration** (for each traffic density):
   ```
   Low:       Should be ~100ns (10 cycles)
   Medium:    Should be ~200ns (20 cycles)
   High:      Should be ~300ns (30 cycles)
   Very High: Should be ~400ns (40 cycles)
   ```

2. **Yellow Phase Duration**:
   ```
   Should always be 30ns (3 cycles)
   ```

3. **All-Red Duration**:
   ```
   Should always be 20ns (2 cycles)
   ```

4. **Complete Cycle Time**:
   ```
   With all medium traffic (20 cyc green each):
   = 4 × (20 + 3 + 2) = 100 cycles = 1000ns
   ```

5. **Emergency Response Time**:
   ```
   Should be ≤ 2 clock cycles (20ns) from emergency assertion
   ```

### Functional Checks

- [ ] All four directions cycle in order
- [ ] No state is skipped
- [ ] Timer counts down correctly in each state
- [ ] Green duration varies with traffic density
- [ ] Yellow duration is constant
- [ ] Emergency interrupts immediately
- [ ] Emergency gives green to correct direction
- [ ] System resumes normal operation after emergency
- [ ] No two directions have green simultaneously
- [ ] All-red interval always present between direction changes

1. Verify adaptive timing works correctly

3. Validate safety (no conflicting greens)
4. Check state sequencing

The VCD file contains all internal signals, making it possible to debug any issue or verify any aspect of the design's behavior.
